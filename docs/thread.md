
## 需求

1. 滚动加载列表
2. 重命名、删除、置顶、反置顶
3. 列表按更新时间排列，以上动作都会更新会话的更新时间，让会话移动到列表第一个
4. 置顶会话单独一个列表，脱离普通会话列表，直接展示全部列表

## 无限滚动

`IntersectionObserver + useInfiniteQuery + nextCursor` 分页方案

### 为什么在无限滚动场景下要使用 nextCursor 方案而不是 current/offect ?

方案 A：current/offset 方案 B：nextCursor 方案

优势 1：乐观更新更方便

- 在已请求列表里重命名会话、在旧会话继续发送消息时：A/B 方案都可以乐观更新，不影响继续请求列表
- 在已请求列表里删除会话、置顶时：A 方案要么重新请求列表，要么前端在请求下个列表时 OFFSET - 1，否则会漏一个；B 可以乐观更新每影响
- 通过搜索定位到未请求的会话时，重命名、继续发送消息时：A 为了乐观更新只能让前端请求下个列表时 OFFSET + 1，否则会漏一个；B B 可以乐观更新没影响
- 删除/置顶未加载条目时，A/B 方案都不需要参与

优势 2：多标签页更新会话，B 方案不会影响其他会话继续加载列表，A 方案下一定会漏项，因为下次请求的 OFFSET 是前端自己算的，它不知道其他页面更新了会话。
